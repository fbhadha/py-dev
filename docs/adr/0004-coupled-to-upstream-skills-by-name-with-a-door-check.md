# Stay coupled to Matt Pocock's and Google's skills by name, verified at the door

Our skills call upstream skills by exact name (`grilling`, `tdd`, `code-review`, `codebase-design`, `domain-modeling`, the vendored `adk-*`) and never copy their text, so upstream updates flow through. The risk is renames: five of his skills were renamed and four deleted in the last year. So `py-intake` and `ask-dev` verify at session start that every upstream name we depend on exists and is model-invoked, and report the changelog entry if not; a CI script does the same against a pinned upstream commit. We rejected vendoring a frozen copy because it would make this repo the maintainer of thirty skills it did not write, which is the reason for choosing him in the first place. Two exceptions: Google's ADK skills are vendored verbatim (they are not shipped as an installable plugin) and refreshed by script at a pinned commit; and his `implement` body (five lines, MIT) is restated in `py-implement` because user-invoked skills cannot be called by other skills.
