# The deterministic gates live in the target repo; harness hooks are a convenience on top

Every rule that can be checked mechanically (ruff rule set, strict types, import-linter layers, the file-size, assertion, prompt-in-comment and weakened-test gates, mutation score) is installed into the target repository as pre-commit hooks and one CI workflow by `py-intake`, and that is the only enforcement we rely on. Harness hooks (Claude Code, Copilot, Codex) run the same scripts for faster in-session feedback but are best-effort: Copilot's command hooks fail open on timeout, Codex's return contracts are unverified, and a plugin cannot be assumed installed. We chose this because constraint violation by agents rises over time when rules live only in prose, and because a repo must behave identically whether the commit came from Claude, Copilot, Codex or a human. The cost is that a repo without pre-commit installed has no gate until intake runs.
